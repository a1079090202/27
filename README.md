# 水站配送与空桶押金台账

Node.js + Express + SQLite(better-sqlite3) + EJS + 原生 JS。
解决三本乱账：

1. **空桶押金对不上**——押金走独立台账，只允许「收」「退」新增，数据库触发器禁止 UPDATE/DELETE；
   退桶按 FIFO 钉到具体每一笔历史收款（哪张收据、什么标准收的就按什么标准退，2019 年的老收据也翻得到底）。
2. **押金抵扣不落账、同一笔押金被重复支取**——回执用客户「账上已有押金桶」抵扣新押金桶时，写入**押金抵扣台账**（`deposit_offset`），
   逐桶 FIFO 钉到当初的历史收款。它是担保置换（旧押金的担保从旧桶转到新桶，不退钱、可退余额不变），但笔笔留痕。
   每个收款批次有一次性的**直接池**（桶数 − 已直接退款 − 已被置换占用）：置换只做一层，再轮换必须交回实物空桶或新收押金；
   已置换在保的桶退桶时，退款沿置换链（`deposit_refund_alloc.via_offset_id`）钉到原始收据。
   写事务内即拒绝超额支取，日结另有全库体检——不会出现「对账全平但同一笔押金担保了两次又退了现金」。
3. **空桶回收账实脱钩**——空桶走**实物台账**（`empty_bucket_ledger`，送达收回 / 退桶交回两通道，只增不改）；
   硬约束「每个客户累计交回空桶 ≤ 累计接收桶数（含 2019 历史补底）」，多报/有物无账在录回执或退桶当下即拒，看板与日结列异常户。
4. **送错楼栋**——回执同时登记「回单楼栋 / 实际送达楼栋」，不一致立刻标红，看板和日结都能看到。
5. **日结假平衡**——新押金必须足额（水款可挂账、押金不可欠，欠水款/欠押金分开列示）；日结 11 项自动对账
   （含收款批次超额支取、在保置换超额退出、全库欠押金等跨表体检）；支持**硬封账**：全平才能封、封账日及以前拒绝补录，
   封账快照固化、重算漂移自动标红。

## 启动

```bash
npm install
npm run seed     # 初始化数据库并写入样例数据（自动清空重建）
npm start        # http://localhost:3000
```

首次使用请先在页面右上角填写**操作人**（开单、分派、回执、退桶都强制留操作人和时间）。

## 重置数据

```bash
npm run reset    # 等价于 npm run seed：删除 data/water.db 后重建并重新灌入样例数据
```

重置是物理删除数据库文件（押金、抵扣、空桶三类台账均禁止改/删，日常使用中不允许改数字，只有整库重置）。
也可以指定别的库文件：`DB_FILE=/data/xxx.db npm start`。

## 验收演示（脚本自动走一遍）

```bash
npm run accept
```

脚本在**当天**依次完成：开五单 → 分给两个师傅 → 录三张回执（其中一单重复提交，验证被拦截且零改动）
→ 退两个桶（含 2019 年老收据客户，退款按当年 30 元/桶标准）→ 出日结，并把押金台账每笔钱的源头打印出来核对。
同时验证：账上押金桶抵扣已落台账并 FIFO 钉源头、同一笔押金重复担保被令牌模型拦截、新押金不足额被拒、
凭空多报空桶被账实硬约束拦截且零落地、台账/分配表/回执/封账快照触发器、硬封账时间闸与封账后漂移检测。
脚本幂等：每次执行会自动重置样例库后重跑。

## 业务规则

| 环节 | 规则 |
|---|---|
| 客户档案 | 楼栋、水牌号、电话；报电话可查历史订单与桶数（`/query`） |
| 开单 | 品牌 + 数量，「押金桶 / 客户自有桶」分行登记；开单不收押金 |
| 押金 | 送达回执时结算：押金桶依次用「账上押金桶的可置换直接池（担保置换）→ 当场收回空桶」抵扣，剩余才收新押金；同一笔押金只允许置换一次 |
| 押金足额 | 现金必须先覆盖本次新收押金（`实收 ≥ 新押金`，不足当场拒）；水款允许挂账，未收款拆「欠水款 / 欠押金」列示（押金优先冲抵口径） |
| 押金台账 | 只能新增 collect/refund；SQLite 触发器禁止修改、删除；每行带滚存余额与操作人；两张 FIFO 分配表同样不可改删 |
| 押金抵扣台账 | `deposit_offset(+_alloc)`：账上余额抵扣时新增，FIFO 钉到历史收款批次；只置换担保、不退钱、可退余额不变；触发器禁改删 |
| 空桶实物台账 | `empty_bucket_ledger`：送达收回(recover) / 退桶交回(refund_in)，只增不改；硬约束「每客户累计交回 ≤ 累计接收」，超出当场拒 |
| 退桶 | 按根收款批次单一 FIFO（根内先直接池、后在保置换），金额由原始收款自动算出，不足拒退；`deposit_refund_alloc` 钉退款→原收据，经置换退出的桶带 `via_offset_id`；交回空桶同步入实物台账 |
| 分派 | 订单分派给师傅，可改派；分派/改派均留痕 |
| 回执 | 一单一回执：服务层先查重 + 数据库 `receipts.order_id UNIQUE` 双保险，重复提交不改任何数；回执一经录入触发器禁改删，已送达订单同样不可改 |
| 楼栋 | 回单楼栋与实际送达楼栋不符即标红 |
| 日结 | 四笔账：现金净流入、未收款项（拆欠水款/欠押金）、押金余额变动、空桶实物回收；11 项自动对账全部平衡才算平 |
| 封账 | 日结页可按日封账（全平方可封、支持零业务日、必须按日连续，首日为锚点）；封账日及以前拒绝回执/退款落入（时间闸）；快照固化在 `daily_close` 且不可改，重算与快照不一致即在日结页标红；看板提醒昨日未封账。冲正只能走次日 |
| 催单 | 开单/分派超过 24 小时未录回执的订单，看板自动列出 |

金额一律以「分」整数存储，页面显示元。

## 目录结构

```
src/
  db/schema.sql          建表 + 台账/分配表/回执/已送达订单/封账快照不可变触发器
  models/                数据访问层：customer/order/receipt/deposit/bucket（空桶实物）/close（封账快照）/driver/product/log
  services/              业务编排：orderService（开单/分派/幂等回执+令牌抵扣+押金足额+账实/封账闸）、
                         depositService（收退/归并 FIFO/via 置换链）、closeService（封账/时间闸/漂移检测）、
                         reportService（日结 11 项对账）、customerService（电话查单）
  routes/                薄路由：orders/deposits/buckets/customers/reports
  views/                 EJS 页面 + 原生 JS（含空桶台账页 buckets/、日结封账区）
scripts/seed.js          样例数据：12 客户、3 师傅、一周订单（含 2019 老收据、送错楼栋、超24h催单）
scripts/accept.js        验收脚本（95 项断言：三重支取回归、押金足额、via 置换链、封账时间闸/漂移、触发器等）
```

## 旧版本数据库升级

`src/db/index.js` 启动时执行幂等结构引导：旧库会自动补 `deposit_refund_alloc.via_offset_id` 列和新索引、
创建 `daily_close` 表与新触发器，无需手工迁移，可重复启动。
注意：升级前若库里存在「同一笔押金被重复担保」或欠押金的历史脏数据，日结对账会显示不平、无法封账；
样例/开发库直接 `npm run seed -- --reset` 重建即可。
