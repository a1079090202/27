# 水站配送与空桶押金台账

Node.js + Express + SQLite(better-sqlite3) + EJS + 原生 JS。
解决两本乱账：

1. **空桶押金对不上**——押金走独立台账，只允许「收」「退」新增，数据库触发器禁止 UPDATE/DELETE；
   退桶按 FIFO 钉到具体每一笔历史收款（哪张收据、什么标准收的就按什么标准退，2019 年的老收据也翻得到底）。
2. **送错楼栋**——回执同时登记「回单楼栋 / 实际送达楼栋」，不一致立刻标红，看板和日结都能看到。

## 启动

```bash
npm install
npm run seed     # 初始化数据库并写入样例数据（自动清空重建）
npm start        # http://localhost:3000
```

首次使用请先在页面右上角填写**操作人**（开单、分派、回执、退桶都强制留操作人和时间）。

## 重置数据

```bash
npm run reset    # 等价于 npm run seed：删除 data/water.db 后重建并重新灌入样例数据
```

重置是物理删除数据库文件（押金表禁止改/删，日常使用中不允许改数字，只有整库重置）。
也可以指定别的库文件：`DB_FILE=/data/xxx.db npm start`。

## 验收演示（脚本自动走一遍）

```bash
npm run accept
```

脚本在**当天**依次完成：开五单 → 分给两个师傅 → 录三张回执（其中一单重复提交，验证被拦截且零改动）
→ 退两个桶（含 2019 年老收据客户，退款按当年 30 元/桶标准）→ 出日结，并把押金台账每笔钱的源头打印出来核对。
脚本幂等：每次执行会自动重置样例库后重跑。

## 业务规则

| 环节 | 规则 |
|---|---|
| 客户档案 | 楼栋、水牌号、电话；报电话可查历史订单与桶数（`/query`） |
| 开单 | 品牌 + 数量，「押金桶 / 客户自有桶」分行登记；开单不收押金 |
| 押金 | 送达回执时结算：押金桶先用「账上已有押金桶 + 当场收回空桶」抵扣，剩余才收新押金 |
| 押金台账 | 只能新增 collect/refund；SQLite 触发器禁止修改、删除；每行带滚存余额与操作人 |
| 退桶 | FIFO 匹配历史收款批次，金额由原始收款自动算出，不足拒退；`deposit_refund_alloc` 记录退款→原收据对应关系 |
| 分派 | 订单分派给师傅，可改派；分派/改派均留痕 |
| 回执 | 一单一回执：服务层先查重 + 数据库 `receipts.order_id UNIQUE` 双保险，重复提交不改任何数 |
| 楼栋 | 回单楼栋与实际送达楼栋不符即标红 |
| 日结 | 三笔账：现金净流入、未收款项、押金余额变动；4 项自动对账全部平衡才算平 |
| 催单 | 开单/分派超过 24 小时未录回执的订单，看板自动列出 |

金额一律以「分」整数存储，页面显示元。

## 目录结构

```
src/
  db/schema.sql          建表 + 押金不可变触发器
  models/                数据访问层：SQL 直接写在这里（customer/order/receipt/deposit/driver/product/log）
  services/              业务编排：orderService（开单/分派/幂等回执）、depositService（收退/FIFO）、
                         reportService（日结对账）、customerService（电话查单）
  routes/                薄路由：只做参数解析与跳转，不堆业务
  views/                 EJS 页面 + 原生 JS
scripts/seed.js          样例数据：12 客户、3 师傅、一周订单（含 2019 老收据、送错楼栋、超24h催单）
scripts/accept.js        验收脚本
```
